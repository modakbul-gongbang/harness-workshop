# TODO 타입과 저장소

`todo.ts`의 Todo는 내부 소유자를 포함하고 TodoView는 공개 응답 타입이다.
`todo-repository.ts`는 실제 SQLite 읽기와 쓰기를 맡는다.

## 데이터 불변식

- 소유자는 호출자가 서버 세션에서 얻은 값이다.
  요청 본문의 owner를 신뢰하거나 repository에서 쿠키를 읽지 않는다.
- 목록은 소유자 조건과 id 내림차순 정렬을 함께 유지한다.
- 수정·삭제는 `id`와 `owner`를 같은 SQL의 WHERE에 넣는다.
  먼저 ID만 조회해서 권한을 확인하는 별도 경로를 만들지 않는다.
- 없는 ID와 타인의 ID는 같은 TodoNotFound로 표현한다.
  타인 데이터의 존재 여부나 제목을 오류에 싣지 않는다.
- SQL 값은 바인딩한다.
  제목·소유자·ID를 SQL 문자열에 붙이지 않는다.
- SQLite의 completed 정수는 저장 경계에서 boolean으로 바꾼다.
  DB 행을 그대로 API 응답으로 내보내지 않는다.
- 단일 쿼리에 불필요한 트랜잭션·인터페이스 계층을 추가하지 않는다.
  테이블 생성·시드는 상위 `database.ts`의 책임이다.

[백엔드 가이드](../../../docs/guides/backend.md)를 읽고 실제 DB를 사용하는 소유자 격리·정렬·CRUD 테스트로 확인한다.
동작을 유지하는 구조 변경 때문에 기존 행동 기대값을 바꾸지 않는다.
