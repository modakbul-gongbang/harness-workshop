# 브라우저 화면과 상호작용

`todo-app.tsx`는 목록·행 편집·삭제 확인을, `login-form.tsx`는 로그인 전송 상태를 담당한다.
`api.ts`가 HTTP 응답·CSRF 요청·인증 만료·표시할 오류를 처리하는 공통 경계다.

## 수정 경계

- 브라우저 네트워크 처리는 기존 `api.ts`를 확장한다.
  컴포넌트마다 fetch·CSRF·오류 변환을 복제하지 않는다.
- TODO 표시는 `TodoView` 타입을 사용한다.
  서버 도메인의 타입만 `import type`으로 참조할 수 있으며 DB·세션 실행 코드는 가져오지 않는다.
- 변경 성공 뒤 목록을 다시 읽어 서버 결과를 표시하는 현재 흐름을 유지한다.
  저장 성공 후 재조회 실패를 저장 실패로 바꿔 같은 POST를 다시 보내지 않는다.
- loading·빈 목록·조회 실패·변경 pending을 구분한다.
  개수는 표시하는 실제 목록에서 계산하고 오류를 빈 배열로 숨기지 않는다.
- 행의 임시 제목은 편집 상태 안에서 관리하고 key는 TODO id를 사용한다.
  편집 취소와 저장 뒤 focus 복귀, 삭제 확인의 취소 동작을 보존한다.
- 네트워크 실패 뒤 버튼을 다시 사용할 수 있어야 한다.
  인증 만료는 기존 로그인 이동 흐름에 연결한다.

상세 UX·키보드·모바일 기준은 [화면 가이드](../../docs/guides/frontend.md)를 읽는다.
HTTP 테스트의 HTML 문자열 검사는 실제 클릭·focus·줄바꿈 검증을 대신하지 않는다.
