# status-filter

확정 여부: **확정**, 교육 계약에 따른 실습용 PRD이며 starter에서 미구현.

## 문제 / 범위

완료한 항목이 쌓이면 남은 할 일을 골라 보기 어렵다.
GET `/api/todos?status=all|active|completed`와 화면의 전체/미완료/완료 선택을 추가한다.
생략은 all과 같고 알 수 없는 값/빈 값은 일관된 400이다.

## 비범위 / 보존 동작

검색, 페이징, 통계, 스키마, 계정, 서비스 추출은 제외한다.
항상 본인 데이터만 id 내림차순, 같은 DTO/CRUD/CSRF/오류를 유지한다.
필터는 페이지 메모리 상태이며 새로고침 기본은 전체다.
선택 필터에서 생성/완료/되돌리기/삭제 후 목록을 다시 조회하고 현재 선택을 유지한다.

## 결정 근거

교육용 확정 계약은 본문과 기본 계약이다.
API 필터의 정답을 현재 미구현 코드에서 유추하지 않는다.
필터 추가는 기능 변경이며 기존 버그 수정으로 꾸며 FAIL 이력을 만들지 않는다.

## 완료·검증 조건

| ID | 완료 조건 | 검증 조건 |
| --- | --- | --- |
| AC-01 | 생략/all은 기존 목록과 동일하다. | 같은 fixture에서 생략/all 응답이 기존 본인 목록과 같고 id 내림차순·동일 필드인지 실제 HTTP로 비교. |
| AC-02 | active는 미완료만, completed는 완료만 반환한다. | minsu 미완료 A·완료 B, jiyun 미완료 C·완료 D에서 minsu active는 A만, completed는 B만 반환. 해당 상태가 없으면 []. 실제 DB API로 검사. |
| AC-03 | 잘못된 status와 빈 값은 400 {code,message}다. | invalid/빈문자 요청의 코드와 오류 구조 검사. |
| AC-04 | 한국어 전체/미완료/완료 선택과 선택 상태가 보인다. | 브라우저 키보드 이동/선택, 모바일 렌더, 조건에 맞는 행과 빈 결과 확인. |
| AC-05 | 변경 후 선택 필터를 유지하고 목록이 갱신된다. | completed에서 신규 생성은 숨김, active에서 완료 시 사라짐, completed에서 되돌리면 사라짐을 UI로 확인. |
| AC-06 | 기본 CRUD와 모든 가이드를 보존한다. | 기존 CRUD·권한 테스트 재사용, 공통 verify 통과, G-ID별 독립 검토, 스키마/계정 변경 없음 확인. |

## 질문

미해결 질문 없음.
조건에 맞는 결과가 없으면 “조건에 맞는 할 일이 없어요.”와 전체 보기 액션을 표시한다.
