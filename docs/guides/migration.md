# G-MIGRATION: DB와 설정

- 두 실습 ticket은 스키마/시드/계정/DB 설정을 바꾸지 않는다. 변경 필요가 생기면 PRD 범위를 먼저 다시 확정한다.
- SQLite 파일 데이터와 최초 시드 표식을 유지한다. 삭제한 TODO를 재기동 때 재생성하지 않는다.
- `data/`는 Git 제외다. reset은 서버를 종료하고 해당 샘플의 DB만 지우는 명시적인 사용자 작업이다.
- 환경/설정은 `docs/architecture.md`의 코드 레지스트리와 Next CLI 실행 인수를 따른다.
- 실제 서비스 전환은 인증/배포/DB 마이그레이션의 별도 계약이 필요하며 이 실습에 섞지 않는다.

## 설정·영속성 변경이 실제로 필요한 경우

1. 바꿀 환경 키·스키마·기존 데이터에 미치는 영향과 되돌리는 방법을 PRD에 적는다.
2. 환경 키는 `src/server/config.ts`에서 필수 여부·형식·부재 동작·서버 범위를 선언하고 `.env.example`을 함께 갱신한다.
   기동 검증 실패에는 키와 오류 종류만 남기고 값을 노출하지 않는다.
3. DB는 새 임시 DB와 기존 형식의 임시 DB 각각에서 기동·재기동·저장 결과를 확인한다.
   시드의 존재 여부를 TODO 행 수로 추정하지 않고 최초 시드 표식을 유지한다.
4. 세션 키 저장 방식을 바꾸면 기존 쿠키와 서버 세션의 유효성에 미치는 영향도 명시한다.
5. 실제 사용자 DB의 초기화·변환은 별도로 승인된 데이터 작업에서 수행한다.

검증용 `WORKSHOP_DATA_DIR`은 직접 만든 임시 디렉터리를 사용한다.
로컬 샘플 DB를 지우는 것은 마이그레이션 성공의 증거가 아니다.
