# TypeScript 작성 규칙

- 기존 코드처럼 들여쓰기 2칸, 큰따옴표, 세미콜론을 사용한다.
  파일명은 kebab-case, 함수·변수는 camelCase, 타입·컴포넌트는 PascalCase로 쓴다.
  Next의 예약 파일명은 프레임워크 규칙을 따른다.
- 프로젝트 모듈은 기존 `@/` alias를 사용하고 타입 전용 의존성은 `import type`으로 구분한다.
- strict 검사를 유지하고 `any`, `@ts-ignore`, 이중 타입 단언으로 입력 검증을 우회하지 않는다.
  외부 입력은 unknown에서 시작해 경계에서 좁힌다.
- 기존 오류 타입과 변환 함수를 확장한다.
  catch에서 오류를 성공값·빈 목록으로 바꾸지 않는다.
- 주석은 이유·제약·공개된 실습 예외에 쓰고 코드 동작을 그대로 되풀이하지 않는다.
- 설치된 Next·Zod·React의 타입과 문서를 먼저 확인하고 기존 기능으로 해결한다.
  스타일 검사기의 실제 기준은 `eslint.config.mjs`이며 모든 문장 규칙이 자동 강제되는 것은 아니다.
