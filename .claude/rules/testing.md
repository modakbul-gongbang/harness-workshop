# 테스트 작성 규칙

- 테스트 이름에 보호하는 계약과 관찰 가능한 결과를 드러낸다.
  기대값의 출처는 기본 계약 또는 확정 PRD에 둔다.
- 기존 node:test·unittest와 실제 HTTP/DB/CLI fixture를 확장한다.
  동작 없는 위임 함수마다 단위 테스트를 붙이지 않는다.
- 임시 디렉터리·포트·프로세스의 소유권과 종료 책임을 fixture에 둔다.
  readiness와 cleanup에는 종료 기한을 둔다.
- 실패 메시지에는 기대값·실제 결과·관련 진단을 포함하되 자격증명과 사용자 내용을 남기지 않는다.
- 테스트 삭제·skip·기대값 변경으로 실패를 덮지 않는다.
  중복·구현 종속 테스트 정리는 보호하는 계약이 유지되는 근거와 함께 허용한다.
- mock 허용 경계·회귀·mutation·완료 기준은 `docs/guides/testing.md`를 따른다.
