확정 여부: **초안**

## 문제 / 범위

누구의 어떤 문제를 해결하고 어떤 동작을 바꿀지 쓴다.

## 비범위 / 보존 동작

바꾸지 않을 동작과 응답·정렬·소유자·빈 상태 등 중요한 회귀 보호 대상을 적는다.

## 결정 근거

중요한 사용자 답변과 확정 계약을 짧게 옮긴다.
인터뷰 D-ID가 있으면 연결하되 로컬 기록 없이도 뜻과 근거를 알 수 있게 쓴다.
현재 구현에서 관찰한 사실과 사용자 제품 결정을 구분한다.

## 관련 가이드

`docs/guides/backend.md`, `docs/guides/frontend.md`, `docs/guides/testing.md`, `docs/guides/migration.md`.

## 완료·검증 조건

| ID | 완료 조건 | 검증 조건 |
| --- | --- | --- |
| AC-01 | 특정 상황과 입력에서 행동하면 관찰할 수 있는 결과 | 독립적인 기대값과 확인할 경계, 예: 두 사용자 혼합 DB를 실제 API로 조회하여 본인 미완료 A만 반환 |

정상 흐름과 중요한 실패·경계·복구를 골라 구체화한다.
버그 수정은 재현 입력·수정 전의 잘못된 결과·올바른 기대 결과를 적는다.
동일한 기대값의 회귀 테스트를 수정 전후 실행하고 실제 실패 이유를 남기는 절차는 테스트 가이드를 따른다.
구현 내부 호출 횟수나 함수 이름을 행동의 정답으로 삼지 않는다.

## 검증 범위

| Surface | 적용 | 이유 |
| --- | --- | --- |
| tests | required | 공통 명령으로 기존 보호와 변경한 동작의 회귀를 확인한다. |
| api | required | API·데이터·권한에 미치는 구체적인 영향을 적는다. |
| ui | required | 사용자 흐름·화면에 미치는 구체적인 영향을 적는다. |

API·UI 영향이 없으면 해당 행의 적용을 not-applicable로 바꾸고 근거를 적는다.
실행 불가인 검증을 not-applicable로 바꾸지 않는다.
표의 tests/api/ui 이름과 required/not-applicable 값은 gate가 읽는 계약이다.

## 질문

미해결 제품 결정을 적고 답을 받은 뒤 본문과 기대 결과에 반영한다.
미해결 항목이 없으면 “미해결 질문 없음”으로 적는다.
사용자 답변·확정 계약에 근거하여 정답과 누락 조건을 확인한 뒤 확정 여부를 **확정**으로 바꾼다.
